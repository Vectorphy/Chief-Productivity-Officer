Random useful bits of info and thoughts and ideas:
    
    Note 1: storing guild object is very useful
            as it stores key information like channel and member information
            thereby reducing API calls to Discord (helps stay under rate limit)
    
    Note 2: Deciding to use guild object for all class internal functions, 
            and using ID (obtained from guild Object info) for all cross-class functions
    
    Note 3: Need to use another function to setup_group_resources()
            bc I can't have async functions in the constructor

    Note 4: Whenever a discord command or interaction is used, in that function, 
            we first defer it, so that interaction 3 second timeout is not triggered
            then we use interaction.followup.send() to send any messages required

    Note 5: If you're handling errors and logging,
            it's better to handle it inside the function you're calling
            rather than the caller, to keep the caller code clean
            Caller - the scope which calls the function / object / attribute
            Callee - the function / object / attribute that's BEING CALLED
